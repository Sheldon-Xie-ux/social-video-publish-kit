# 视频发布流程 · 坑位清单与防错设计

> v1 · 2026-11-02 · 基于 10-30 至 11-02 四次完整发布、17 次失败的复盘
> **每次发布前对照本清单，不靠记忆。**

---

## 一、封面：最大的坑（占全部返工的 60%）

### 坑 1：平台会二次裁切，标题放顶部必被切

**现象**：封面设计得好好的，上传后四个平台都只剩中间一条，标题没了。

**原因**：每个平台的展示位比例不同，且**以画面中心为基准裁切**。

| 平台 | 上传比例 | 实际展示 | 裁切损失 |
|---|---|---|---|
| 抖音主页格子 | 3:4 | 3:4（但对 9:16 素材按中心取 3:4） | 上下各 12.5% |
| 小红书笔记格子 | 3:4 | 3:4 | 上下各 12.5% |
| 视频号 | 9:16→3:4、4:3 | 中心裁 | 上下各 12.5% |
| B站首页推荐 | 4:3 | 4:3；列表缩略图按 16:9 | 上下各 12.5% |
| B站个人空间 | 16:9 | 16:9 | — |

**规则**：所有关键元素必须完整落在 **12.5%–87.5%** 的中心裁切区内；标题块建议占 **14%–50%**。任何超出都必须先返工，不得上传。

**验证方法**（必做）：

```python
# 把成品按目标比例做中心裁切，肉眼看一遍
def crop_center(im, W, H):
    r = max(W/im.width, H/im.height)
    im2 = im.resize((int(im.width*r), int(im.height*r)))
    L, T = (im2.width-W)//2, (im2.height-H)//2
    return im2.crop((L, T, L+W, T+H))
```

### 坑 2：一张图套所有比例，人变成「贴纸」

**现象**：竖图硬裁成 16:9 会切头；用「完整放入+模糊补齐」又像贴纸。

**原因**：源图是特写人像（3:4），信息密度集中在中部，任何异比例裁切都难看。

**规则**：**按比例分别生成底图**，不要一张图裁来裁去。

| 用途 | 生成尺寸 | 提示词要点 |
|---|---|---|
| 竖版（抖音/小红书/视频号） | 1024×1792 | 人物从 40% 处出现，上方 35% 留白 |
| 横版（B站） | 1536×1152 | 人物占右侧 60%，左侧 40% 留白放标题 |

### 坑 3：AI 画的文字是乱码

**规则**：**AI 只出人和背景，文字全部用代码压。**
模型画中文必乱码；且文字要能改，不能重新花钱生成。

### 坑 4：封面小字、压眼睛

- 小于标题 60% 的字一律不要
- 眼睛、鼻、嘴不能被任何文字覆盖
- 暖色调，不做冷色/暗调（用户明确要求）

## 二、上传：第二大坑

### 坑 5：大文件上传没完成就点发布

**现象**：点「发布」后页面跳转，但作品没出现；或作品数 +1 但列表看不到。

**原因**：150MB+ 的视频上传需要 5–20 分钟，脚本按固定 sleep 走完就点发布，实际还在传。

**规则**：**必须轮询「上传完成」信号，等到出现再点发布。**

| 平台 | 完成信号 |
|---|---|
| 抖音 | 页面出现「上传完成」 |
| 小红书 | 出现「检测为高清」 |
| B站 | 出现「上传完成」 |
| 视频号 | 出现「删除」按钮 |

**轮询上限**：至少 25 分钟（153MB 实测 21 分钟）。

### 坑 6：视频号的 Shadow DOM 挡文件选择器

**现象**：`DOM.setFileInputFiles` 无效，文件选不上。

**原因**：视频号是 WUJIE 微前端，上传控件在 Shadow DOM 内。

**规则**：用「页面内构造 File」的方式注入：

```js
// 分块注入，避免字符串超限（>512MB 会报错）
window.__chunks = [];
// 每 8MB 一块，解码成 Uint8Array 后 push
const f = new File(window.__chunks, name, {type:'video/mp4'});
const dt = new DataTransfer(); dt.items.add(f);
input.files = dt.files;
input.dispatchEvent(new Event('input', {bubbles:true}));
```

**注意**：单次 `atob` 的 base64 字符串超过 V8 上限（≈512MB）会失败，必须分块。

### 坑 7：小红书发布按钮找不到

**现象**：按文字找「发布」找到的是侧边栏的「发布笔记」，点了没反应。

**规则**：小红书发布按钮是右下角固定定位，用坐标 `(视口宽×0.54, 视口高×0.955)`，或匹配 `XHS-PUBLISH-BTN` 自定义标签。

### 坑 8：视频号短标题规则

- **≤16 字**
- **不能有逗号**（会被拒：「标题包含特殊字符，逗号可用空格代替」）
- 中文标点也有限制

## 三、剪辑与音频

### 坑 9：多机位偏移量算错

**现象**：成片丢了开场，画面和声音差 111 秒。

**原因**：以为「两台设备都从同一时刻开始」，两边都用了同一个 `-ss`。

**规则**：先确定**各自 0 秒在真实时间轴上的位置**：

```
屏幕录制 18:35:46 开始
Pocket    18:37:37 开始
→ Pocket 0s = 屏幕 111s
→ 屏幕用 -ss 111，Pocket 用 -ss 0
```

### 坑 10：ffmpeg 滤镜复用同一路流

**现象**：`Stream specifier matches no streams` 或静默失败。

**规则**：同一输入被多处使用时必须 `split` / `asplit`：

```
[0:v]split=5[v0][v1][v2][v3][v4]
[0:a]asplit=5[a0][a1][a2][a3][a4]
```

### 坑 11：音频 concat 参数写错

**现象**：`Media type mismatch between audio pad and video pad`。

**规则**：视频拼接 `concat=n=N:v=1:a=0`，音频拼接 `concat=n=N:v=0:a=1`。

### 坑 12：在已烧字幕的成片上再叠字幕

**现象**：双字幕。

**规则**：**任何重剪都从原片开始**，不要拿成片当输入。

## 四、字幕

见 `字幕规范.md`。三条最容易犯的：

1. 字号太小（1080×1920 用 **88**，不是 52）
2. 手动断行把词劈开（「MGM学 / 院」）——**交给 libass 自动换行**（WrapStyle=0）
3. 剪过的片子字幕没重排时间轴

## 五、环境

### 坑 13：自动化浏览器占用用户的 Chrome

**现象**：用户点 Chrome，看到的是没有书签、没有日历的空白浏览器，以为数据丢了。

**规则**：自动化一律用 `~/agent-browser/Chrome-Agent.app` + `~/.chrome-cdp-profile`，
**绝不碰** `/Applications/Google Chrome.app` 和用户 profile。

### 坑 14：后台改封面入口点不动

**现象**：视频号「修改描述和封面」、抖音「编辑作品」悬停后图标出现，但程序点击无反应。

**原因**：这类操作依赖 hover 状态，CDP 分两次派发 `mouseMoved` + `mousePressed` 时 hover 状态可能已被重置。

**规则**：封面**在上传时一次做对**，不要指望事后改。
如果必须事后改，用「同一个 CDP 会话内连续派发、不间隔」的方式，或直接重新上传。

## 六、发布前检查（逐项打勾）

- [ ] 封面：标题在垂直 20%–45%，缩到手机大小能一眼读完
- [ ] 封面：模拟 3:4 中心裁切后标题仍完整
- [ ] 封面：眼睛没被文字压住，暖色调
- [ ] 封面：每个平台比例单独出图，不是一张裁到底

- [ ] 字幕字号 ≥ 88（1080×1920）
- [ ] 上传：等到「上传完成」再点发布
- [ ] 发布后：回列表确认作品已出现、封面正确
- [ ] 发布后：确认没有被判重复内容（同一素材不要当天多次上传）
