# 发布自检清单 · 事故复盘与硬性规则

> 2026-10-30 建。来自一次真实翻车：四个平台发同一条视频，只有抖音完全正确。

## 一、这次出了什么错

| 平台 | 问题 | 根因 |
|---|---|---|
| 抖音 | ✅ 正确 | 走的是最成熟的脚本 |
| 视频号 | 封面没传上 | 微前端（WUJIE）重新挂载把已注入的文件清空；脚本没校验就点了发布 |
| 小红书 | 没有封面 | **平台限制**：网页版不支持自定义封面，只能选智能推荐或首帧 |
| B站 | 封面被裁 | 4:3 图里文字贴左下角，B站按 16:9 显示时切掉了 |

二次修复时还出了两个新错：删错了视频（按坐标猜的删除按钮）、封面校验条件写得太松（假通过）。

## 二、根因归纳（三条）

1. **每一步都没有"做了之后确认真做了"**
2. **封面依赖平台接口，而接口行为不稳定**（视频号会丢、小红书没有、B站会裁）
3. **用坐标点按钮**，页面一滚动就点错对象

## 三、硬性规则（以后必须执行）

### 规则 1：每一步都要断言，不通过就停

```
注入视频 → 断言视频出现在编辑器 → 填字段 → 断言字数对 → 设封面 → 断言封面预览变了 → 发布 → 断言跳转/列表出现
```

任何一步断言失败：**立即停止，不往下走**，并报告哪一步失败。绝不允许"先发出去再说"。

### 规则 2：封面用首帧，不用平台接口

**这是最重要的一条。**

把封面做成视频的**前 0.6 秒画面**，这样所有平台抓首帧都自动是设计好的封面：

```bash
ffmpeg -loop 1 -t 0.6 -i 封面16x9.jpg -i 成片.mp4 \
  -filter_complex "[0:v]scale=1920:1080,setsar=1,trim=duration=0.6,setpts=PTS-STARTPTS[a];\
[1:v]setpts=PTS-STARTPTS[b];[a][b]concat=n=2:v=1:a=0[v];\
[1:a]adelay=600|600,apad=pad_dur=0.6[aud]" \
  -map "[v]" -map "[aud]" -c:v libx264 -crf 18 -c:a aac 成片-首帧版.mp4
```

好处：
- 视频号不会丢
- 小红书没有自定义封面也能用上
- B站、抖音即使接口失败也有兜底

代价：视频开头多 0.6 秒封面卡（行业标准做法，观众不会觉得突兀）。

### 规则 3：按钮不按坐标点，按文本定位 + 同一行约束

删错视频就是因为按 `y=446` 猜。正确做法：

```js

const btn = /* 找「删除」且 |y - rowY| < 40 的元素 */;
```

### 规则 4：发布后回查列表

发布脚本的最后一步不是"点了发布"，而是：
1. 断言 URL 跳到列表页
2. **刷新列表，确认新作品出现且封面正确**
3. 把列表截图发出来

### 规则 5：封面尺寸按平台分，别想着一图通用

| 平台 | 尺寸 | 文字安全区 |
|---|---|---|
| 抖音竖封面 | 1080×1440 | 底对齐 86% |
| 抖音横封面 | 1600×1200 | 左对齐，垂直居中 |
| B站首页推荐 | 1440×1080（4:3） | **文字必须水平+垂直都居中**，会被裁成 16:9 |
| B站个人空间 | 1920×1080（16:9） | 同上 |
| 小红书 | 1080×1440 | 手传，同抖音竖版 |

## 四、发布前人工自检（30 秒）

发出去之前，把这 5 条过一遍：

- [ ] 每个平台的视频**时长一致**（防止传错文件）
- [ ] 每个平台的封面**在列表页能看到设计稿**（不是默认帧）
- [ ] 标题字数没超（抖音 30 / 小红书 20 / 视频号 16 / B站 80）
- [ ] 简介里有话题标签
- [ ] 多平台默认错开发布；间隔 ≥2 小时是**内部防重复策略**，不是已证实的平台规则；同一内容当天多平台发布不禁止

## 六、封面两条铁律（2026-10-30 追加）

### 铁律 1：封面上不允许出现小字

**任何小于标题 60% 的字，一律不许放。**

原因：手机信息流里封面只有拇指大小，小字等于噪点，不但没用还会显得脏。
需要的信息（机构名、活动名）就**当成标题的一行**，用同样大的字写。

反例：底部压一条「南京大学 · 工程管理前沿讲座」小黑条（34px），在手机上完全看不清。
正例：四行大字，第一行就是「南京大学」。

### 铁律 2：文字必须放在「多重裁切安全区」里

平台会对同一张图做多次裁切：

| 平台行为 | 实际裁切 |
|---|---|
| 小红书格子 | 9:16 首帧 → 3:4 |
| 抖音主页格子 | 9:16 → 3:4 |
| B站首页推荐 | 4:3（常按 16:9 显示） |
| 视频号 | 9:16 → 3:4 与 4:3 两种卡片 |

**做法**：文字块**垂直居中**，占画面高度不超过 60%（上下各留 20%）。
这样无论裁成 3:4、4:3 还是 16:9，文字都不会被切。

反例：三行字压在画面底部（y 63%~94%），小红书裁成 3:4 时第三行被切掉。

### 自查

- [ ] 封面放大到手机屏幕大小看，最小那行字能不能一眼读出
- [ ] 把封面按 3:4 从中间裁一刀，文字是否完整
- [ ] 把封面按 16:9 从中间裁一刀，文字是否完整

## 七、浏览器红线（2026-11-02）

1. 自动化一律用 `~/agent-browser/Chrome-Agent.app` + `~/.chrome-cdp-profile`，**绝不碰用户日常 Chrome**
2. 启动：`./start-cdp.sh`；结束：`./stop-cdp.sh`
3. 事故记录：2026-11-01 用 Google Chrome 起 CDP 实例占用了 App，用户看不到自己的书签和日历，误以为数据丢失。**实际数据一条没丢。**
